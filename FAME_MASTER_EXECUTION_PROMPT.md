# FAME CAFÉ — MASTER WEBSITE EXECUTION PROMPT

## Aufgabe

Baue die bestehende FAME CAFÉ Website für Gummersbach zu einer vollständigen, hochwertigen und technisch sauberen Premium-Café-Website aus.

**Design Lock:** Der aktuelle visuelle Stand ist freigegeben. Farbwelt, Typografie, FAME-Wortmarke, Header-Logik, Hero-Komposition, Kreis-Sprache, Half/Half-Elemente und die grundsätzliche Editorial-Richtung werden geschützt. Kein Redesign, kein Framework-Wechsel, keine neue Designrichtung.

Ziel ist: bestehenden Stand schützen, Frontend verfeinern, verifizierte Inhalte vervollständigen, echte/saubere Bildwelt vorbereiten, Scroll-Erlebnis verbessern, Responsive perfektionieren, Performance/Accessibility/SEO absichern und FAME wie eine reale Lifestyle-Café-Marke wirken lassen.

---

## 1. Design Lock

Nicht neu erfinden oder ersetzen:

- Farbwelt
- Header
- FAME-Wortmarke
- Editorial Serif + Clean Sans System
- Half/Half Coffee × Matcha
- Kreis-/Bubble-Sprache
- bestehende gute Kompositionen

Nicht einsetzen:

- generische SaaS-Komponenten
- Template-Karten als Füllmaterial
- Pfeile als dekoratives Hauptmotiv
- Emoji-Icons
- External-Link-Icons bei jedem Link
- generische KI-Illustrationen
- UI-Kit-artige Navigationsbausteine
- unnötige Badges

Kleine Punkte, Linien und reduzierte Marker sind zulässig, wenn sie in die bestehende Designsprache passen.

## 8. Matcha Build Story — korrigierte Datenregel

Kreative Ausgangssequenz:

**Foam → Ice → Coconut Water → Matcha → Lid → Straw**

Aber: `Coconut Water` ist aktuell **nicht als echte FAME-Zutat öffentlich bestätigt**.

Daher gilt für die öffentliche Website bis zur Bestätigung:

**Foam → Ice → Layer → Matcha → Lid → Straw**

`Layer` ist ein neutraler visueller Platzhalter. Sobald die echte Rezeptur bestätigt ist, darf die Sequenz datengetrieben aktualisiert werden.

Die Sequenz soll food/editorial/social wirken — nicht wie eine technische Exploded View.

## 19. Motion System

Bevorzugt:

- Scroll Reveal
- Mask Transitions
- Image Scale
- leichte Parallax
- Sticky Sections
- Text Transitions
- Farbflächenwechsel
- Product Movement
- Scroll Progress
- subtile Microinteractions

- keine Layout Jumps

- `prefers-reduced-motion` berücksichtigen

## 28. QA / Arbeitsreihenfolge

Immer in dieser Reihenfolge:

**AUDIT → DESIGN LOCK → DATA VERIFY → IMAGE SYSTEM → FRONTEND → MOTION → RESPONSIVE → PERFORMANCE → SEO → VISUAL QA → FINAL QA**

Vor größeren Änderungen bestehenden Stand prüfen.

Wenn eine bestehende Variante visuell besser ist, sie behalten.

Visuelle Qualität hat Vorrang vor unnötiger Refaktorierung.

---

## Definition of Done

Nicht fertig, nur weil Code kompiliert.

Fertig bedeutet:

- visuell geschlossene Marke
- kein Template-Gefühl
- keine Fake-Inhalte
- keine Pfeil-/UI-Kit-Rückfälle
- kein horizontaler Overflow
- Mobile bewusst komponiert
- Motion stabil
- bestätigte Daten korrekt
- fehlende reale Daten klar als offene Punkte dokumentiert
- finale FAME-Fotos/Domain/Kontakt nur dann als fertig markieren, wenn wirklich geliefert

## Entscheidungsregel

Technisch fancy vs. visuell hochwertig → **visuell hochwertig**  
Noch ein Element vs. mehr Ruhe → **mehr Ruhe**  
Generischer Café-Look vs. FAME → **FAME**  
Etwas sieht bereits sehr gut aus → **nicht unnötig anfassen**
